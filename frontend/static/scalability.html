Cara Kerja Scale-Up / Down
Meningkatkan kapasitas satu server yang sama dengan menambahkan CPU, RAM, atau storage yang lebih bertenaga. 		Scale-Out / In
Menambah atau mengurangi jumlah node server identik dalam satu pool/cluster yang bekerja sama.
Downtime Ada Downtime (Restart): Server umumnya harus dihentikan (shutdown/reboot) saat memodifikasi ukuran hardware virtual maupun fisik. Zero Downtime: Node baru dapat didaftarkan ke Load Balancer saat traffic berjalan tanpa mengganggu server aktif lainnya.
Batas Kapasitas Ada Batas Maksimum (Hardware Ceiling): Dibatasi oleh spesifikasi tertinggi motherboard/mother-instance yang disediakan penyedia cloud. Hampir Tanpa Batas (Elastis): Dapat menambah puluhan hingga ribuan node sesuai kebutuhan trafik pengguna.
Ketahanan Gagal (Fault Tolerance) Rentan (Single Point of Failure): Jika server tunggal mengalami kerusakan hardware atau kernel crash, seluruh aplikasi tiket mati total. Tinggi (High Availability): Jika salah satu server mati, Load Balancer otomatis mengalihkan beban ke server lain yang masih sehat.
Kebutuhan Tambahan Arsitektur Sederhana: Tidak membutuhkan Load Balancer atau sinkronisasi session state antar-server. Kompleksitas Tambahan: Membutuhkan Load Balancer, shared database terpusat, dan penanganan session yang stateless (misal JWT / Redis).
Biaya (Cost Efficiency) Biaya per upgrade meningkat secara eksponensial pada hardware tier tertinggi; server tetap menyala walau trafik malam hari sepi. Biaya bersifat linear & fleksibel (Pay-As-You-Go): Server bisa dimatikan (Scale-In) saat malam hari untuk memangkas biaya server.
